# Session reports

Create `YYYY-MM-DD-<session>/REPORT.md` for each substantive local-agent iteration.

Use this structure: objective; starting source/environment; changes; tests with actual commands and PASS/FAIL/NOT_RUN/BLOCKED; app/hardware/preview/production status separately; produced artifacts; data/migration/rollback impact; unresolved prerequisites; next bounded task.

Keep credentials, operator capability URLs, raw production UIDs, private contact content and unnecessary local-path/account details out of shared reports. Raw local logs should normally stay under ignored `.local/`. Preserve previous reports and the delivery's `docs/test-evidence/` unchanged.
