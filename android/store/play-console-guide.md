## Data safety rationale for the offline build

The merged app should request only NFC and VIBRATE. Email support opens an unsent composer without card data. No Internet, analytics,
advertising, account, billing SDK or server upload exists. Destinations and
history stay in private preferences. Incoming browser shares are explicit user
actions, confirmed before replacing the destination. NFC deliberately transfers
the chosen URL to a card; warn that anyone can read it. Card UID/readback appear
locally and are not saved to a log. Android 12+ extraction rules exclude app
data from backup/device transfer; older cloud backup is disabled.

Working assessment: no developer collection or third-party data sharing to
declare for this build, subject to review of the precise Console definitions
and user-directed NFC transfer. Local-only processing is excluded from
collection; user-initiated expected transfers have a sharing exception in
[Google's definitions](https://support.google.com/googleplay/android-developer/answer/10787469).
The policy must still explain the local data and card transfer. Reassess the
answers as soon as payment, diagnostics, hosting or a third-party SDK is added.

## Reviewer instructions (copy after physical acceptance)

No account, credentials or purchase is required. nfcraft writes a single HTTPS
link to an unlocked factory-default NTAG215 tag. NFC-capable Android hardware
and that tag type are needed. Other NFC chips, bank cards and access badges
are unsupported. Save a public test URL, use Inspect only to read first, then
turn Inspect only off when ready to write an expendable tag. Hold it still
until Written, Finished or Already done. Inspect mode does not write. Dialogs
pause new scans. Unknown-content overwrite requires confirmation and resets
when the app leaves the foreground. Check the final link with another phone.
History and browser-share confirmation can be reviewed without a physical tag.

Do not upload an engineering screenshot showing a fabricated successful write.
Follow `TESTING.md` on the signed release candidate before claiming compatibility.

## Testing and production sequence

1. Finish public privacy/contact and actual audience/territory decisions.
2. Back up the owner-selected upload key securely; build and verify the signed
   AAB. Keep package `best.tgs.cardwriter`; check availability during first upload.
3. Internal track: owner-selected testers install through Play; verify signing,
   update preservation, supported devices and the complete hardware checklist.
4. Closed track: for a new Personal account, at least 12 testers must stay opted
   in continuously for 14 days before applying for production access. Arrange
   some extra willing testers to tolerate dropouts; do not buy superficial
   opt-ins. Actual testing and application review are required.
5. Record feedback/fixes and answer production-access questions honestly; the
   qualifying period is not automatic approval. See
   [testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465).
6. Review build hash, signing certificate, listing, privacy and final countries
   together before submission. No upload/public rollout was performed here.
